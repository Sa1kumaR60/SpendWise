Problem Statement & Proposed Solution

Addressing personal expense tracking friction and privacy compromises

Problem Statement

Digital payments have caused frictionless spending for students and young professionals. However, traditional record-keeping through paper diaries or spreadsheets is labor-intensive, error-prone, and provides no proactive warning before funds run out.

Why Did We Choose This Problem?

  • Invisible Micro-transactions: Small daily UPI payments add up to major deficits without timely awareness.
  • Commercial Privacy Risks: Existing apps (Mint, YNAB) require linking bank credentials, exposing user data.
  • Lack of Real-time Alerting: Traditional spreadsheets only show totals after the month has passed.

Our Solution — SpendWise

A privacy-first, self-contained MERN web application that provides live category budgeting, proactive threshold alerts, and cash flow analytics with zero external banking dependencies.

Key Project Objectives

  • Multi-Tenant Data Isolation: Strict user-ownership scoping to prevent cross-account data leaks.
  • Proactive 3-Tier Budget Engine: Automated warnings (Normal, Warning ≥80%, Exceeded ≥100%).
  • Relational Integrity Guards: Blocks deletion of categories that have active transactions.
  • Portability & Auditing: Sanitized RFC 4180 CSV export protecting against spreadsheet formula injection.

Entity-Relationship (ER) Model & Schema Mapping

Relational modeling and compound indexing in MongoDB

Relational Cardinality Map

USER (1) ──────────< CATEGORIES (N)
USER (1) ──────────< TRANSACTIONS (N)
USER (1) ──────────< BUDGETS (N)
CATEGORY (1) ──────< TRANSACTIONS (N)
CATEGORY (1) ──────< BUDGETS (N)

Every child entity carries a user: ObjectId foreign key, forming the architectural basis for multi-tenant isolation.

Engine-Level Compound Indexes

  • Budget Uniqueness Index:
    { user: 1, category: 1, month: 1 } (Unique)
    Guarantees a user cannot have two competing budgets for the same category in a month.
  • Category Uniqueness Index:
    { user: 1, name: 1, type: 1 } (Unique)
    Prevents duplicate naming while allowing identical names across different users.
  • Chronological Search Index:
    { user: 1, date: -1 } speeds up dashboard queries.

Proactive Budget Algorithm & Aggregation Pipeline

Real-time database analytics and 3-tier threshold state machine

MongoDB Aggregation Pipeline

const spent = await Transaction.aggregate([
  { $match: {
    user: req.user._id, type: 'expense',
    date: { $gte: start, $lt: end }
  } },
  { $group: {
    _id: '$category',
    totalSpent: { $sum: '$amount' }
  } }
]);

Executes natively within MongoDB engine; returns clean category totals in a single round-trip.

Threshold State Machine

P = ( Total Spent / Limit ) × 100
  • Normal State (P < 80%): Green progress bar. Safe spending position.
  • Warning State (80% ≤ P < 100%): Amber progress bar + Top alert banner warning the user.
  • Exceeded State (P ≥ 100%): Crimson Red bar + Deficit indicator showing overspent funds.

Technical Challenges Faced During Internship

Complex software engineering hurdles resolved during development

1. Cookie Handling Across Decoupled Ports

Browsers block third-party cookies on different localhost ports (5173 to 5000). Resolved by setting up a reverse proxy in vite.config.js so calls route same-origin with credentials: 'include'.

2. Eliminating IDOR Across Multi-Tenant Data

Prevented unauthorized users from editing foreign records by avoiding naked findById() lookups; enforced { _id: id, user: req.user._id } across all controllers.

3. Race-Condition Duplicate Budgets

Rapid double-clicks could bypass application-level checks. Resolved by enforcing compound unique B-tree indexes at the MongoDB engine level, returning HTTP 409 cleanly.

4. Fast Automated Testing Without Corrupting Real Data

Configured mongodb-memory-server with Jest and Supertest, enabling 19 integration tests to run against real database indexes in 31 seconds with zero side effects.

Known Limitations & Future Scope

Planned engineering enhancements for enterprise scalability

Current System Boundaries

  • Manual Transaction Entry: Zero automated bank synchronizations by design to respect privacy.
  • Single Base Currency: Currency codes format visual display symbols ($ , € , £ , ₹) without live FX conversion.
  • Stateless JWT: Tokens remain valid until expiry unless an active Redis token blacklist is maintained.

Roadmap for Future Enhancements

  • Receipt OCR Scanning: Integrating Tesseract.js / Vision API to photograph paper receipts and auto-extract totals.
  • Recurring Subscriptions: Node-cron workers to automatically log recurring rent and utility bills.
  • Progressive Web App (PWA): Service worker caching for installable, offline mobile transaction entry.
  • Multi-Currency Engine: Dynamic conversion using cached foreign-exchange rates.
